# 통합 시연과 배포 준비

## 실행

Node.js 22.18.0에서 검증합니다. `.env.example`을 `.env`로 복사하고 `GEMINI_API_KEY`를 설정합니다. 모델은 `GEMINI_MODEL`로 지정할 수 있습니다. 키 값은 저장소나 검증 기록에 남기지 않습니다.

```sh
npm ci
npm run typecheck
npm run build
npm test
npm start
```

기본 접속 주소는 http://localhost:3000 입니다. AI 키 설정 배너는 실제 분석 성공을 보장하지 않습니다. 키가 없으면 직접 입력·합성 예시 흐름을 확인할 수 있습니다.

## 대표 흐름

- [ ] PAY-001 선택 → 증빙 등록에서 아래 합성 텍스트 분석 → 추출값 수정·확인 → 후보 선택 → 결제에 연결 → 가맹점 확인/카드 미확인 → 문의자료 복사.
- [ ] 같은 내용을 PNG/JPG로 캡처해 텍스트 없이 실제 분석. 결과와 사용 모델·실행 시각 기록.
- [ ] 재분석·값 수정·결제 후보 변경 시 확인 체크가 해제되고, 확인 전 연결되지 않는지 확인.
- [ ] 잘못된 키·외부 실패·429에서 오류와 재시도 안내, 입력·캡처 유지 확인. 모의 오류와 실제 오류는 구분해 기록.
- [ ] PAY-002에서 결제 11/14 → 요청 11/15 → 가맹점 11/16 → 카드 11/18 기록과 출처 확인.
- [ ] PAY-003의 요청 접수만으로 가맹점·카드가 확인 처리되지 않는지 확인.
- [ ] 시연 초기화 후 원래 3건 상태 복원. 재시작 시 메모리 데이터 소멸 확인.

합성 텍스트:

```text
[합성 취소 안내 / 실제 고객 정보 아님]
주문번호: ORDER-001
취소 금액: 50,000원 (KRW)
취소 처리일: 2026-11-19
가맹점에서 전액 취소 처리했습니다. 카드사 반영 여부는 별도로 확인해 주세요.
```

현재 3건은 주문번호·금액·통화가 달라 다중 후보가 나오지 않습니다. 실제 다중 후보 검증에는 별도 합성 fixture가 필요합니다. fixture나 모의 API로 검증한 결과를 실제 AI 검증으로 기록하지 않습니다.

## AWS 배포 준비

현재 AWS 리소스와 배포 URL은 없습니다. 배포 담당·계정·리전·실행 방식을 확정하고 다음을 수행합니다.

1. Node 지원 버전에서 `npm ci`와 `npm run build`를 실행하고 `npm start`로 서버를 구동합니다. 현재 시작 명령도 빌드를 수행하므로 빌드 도구가 포함된 의존성이 필요합니다.
2. 배포 환경에서 `HOST=0.0.0.0`, `PORT`와 Gemini 환경 변수를 설정합니다. 로컬 기본값은 `127.0.0.1:3000`입니다. 키는 배포 환경의 비밀 설정으로 주입합니다.
3. 인증·데이터 격리·초기화 API 접근 제어가 없으므로 팀 전용 접근 제어가 있는 환경에서 시연합니다. 공개 서비스 운영은 이 작업의 완료 범위가 아닙니다.
4. 재시작·다중 인스턴스에서 메모리 저장 상태가 공유되지 않음을 고려해 단일 시연 인스턴스로 검증합니다.
5. 다른 팀원 PC에서 화면·`/api/health`·결제 목록·실제 분석·연결·복사·초기화를 확인합니다. 키 존재만으로 AI 검증을 완료 처리하지 않습니다.
